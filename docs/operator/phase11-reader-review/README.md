## Deliberate exclusions and safeguards

The Team database also contains marketplace_purchases and holder_point_mappings. Its existing reader has no SELECT on those copies. Registry routing requires the Prizes and Points copies, respectively; the proposed Team grants therefore contain only the three Duel tables. The shared Images database correctly receives three table grants for two separately configured logical sources. No sequence grants are required for selecting table rows. No ALL TABLES, future/default privilege grants, role memberships or blanket read roles are used.

Gauntlet source code declares gauntlet_online_reward_events, but the live database lacks it. The new gauntlet.sql proposal grants only the existing gauntlet_runs table and explicitly documents partial coverage. It differs from the earlier aborted all-required-tables provisioning template. It has not been executed and does not repair or conceal the missing table.

The SQL creates a fresh role only and grants CONNECT, schema USAGE and the listed SELECT permissions. ALTER ROLE statements configure only the new reader; they do not grant the reader ALTER or role-creation privileges. PostgreSQL ALTER/DROP powers generally derive from ownership or elevated roles, neither of which is assigned. NOLOGIN prevents accidental use before secure password setup. If public/inherited privileges make the effective permissions unsafe, the transaction aborts; it does not revoke shared grants or alter another account. A failed transaction must be rolled back by the operator.

Do not execute any proposal before explicit approval. For the seven existing roles, review current grants instead of rerunning creation. The live metadata inspection confirmed existing roles have login enabled and no superuser/create-db/create-role/replication/bypass-RLS attributes; all mapped present tables granted earlier report reader SELECT access. This reinspection did not change those grants.

Secure network routing remains a separate issue: public reader connections currently fail certificate validation. No TLS verification bypass is proposed. Reader provisioning alone cannot close schema, import, replay or launch gates.
