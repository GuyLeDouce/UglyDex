# Ecosystem activity model

UglyDex reads legacy history; it never pays rewards, changes game results, or writes to an ecosystem database. Phase 3 extends `CollectorActivity` and `SquigPassportEvent`. Blockchain provenance remains in its existing raw ledger and rebuildable collector projection.

## Event identity and correction

A normalized legacy event uses source system, registered feed/table, durable source row ID and a stable role/slot. A Duel has challenger and opponent slots. Outcome, Collector UUID, timestamp, token and money do not define the key: correcting them updates the same fact. Phase 0 identities remain readable; replay retracts superseded old slots with audit evidence.

`CollectorActivity` now allows an unresolved Collector. It records internal Discord ID/wallet, attribution status, category, visibility, importance, source timestamps, amount/currency/direction, payload hash, correction timestamp and active/retracted status. Its existing source identity and Passport relationship remain. A source record's slots and Passport replacements commit in one advisory-locked transaction. `ActivityCorrection` preserves the prior normalized representation and reason for each material correction, attribution change or slot retraction. No private source story, moderation note, session or provider response is imported.

An updated source row can change a win into a loss, hide an approval, correct a token or retract a burn. Derived statistics read active normalized facts, so they immediately reflect correction. Missing slots are retracted, not deleted. A source row disappearing from an external table is **not** inferred to invalidate an observed fact; rolling scans do not infer deletion from absence. Investigate source deletion with the owner and retain evidence. Corrections remain admin-only.

Bounty votes are aggregate counters, not an invented individual voting ledger. Survival image usage never identifies an NFT or automatically identifies its creator. No generic CHARM balance or lifetime financial ledger exists. Approval notifications, reactions, pool payout copies, and generic payment intents are excluded as duplicate reward authorities. Marketplace refund totals remain separate from gross spending; wagers are not treated as spending or earnings.

## Attribution and assets

Explicit Discord IDs map to the unique external identity (an unclaimed Collector can be reserved); display names are never matching keys. Without Discord, wallet attribution requires an unambiguous, time-bounded Phase 2 VERIFIED/REVIEWED/bounded REVOKED relationship. Conflicting evidence opens a reconciliation case. Missing identity never discards an explicit Squig event.

`activity:reattribute` changes only local attribution with an audit. Historical review/link changes queue `ActivityAttributionJob` atomically through the existing wallet-dirty mechanism. The ecosystem worker processes bounded batches, with generation fencing so a newer review cannot be lost. Pending wallet attribution jobs withhold wallet-attributed public results until refreshed. No external reimport or login-account merge is required.

Only token 1–4444 with explicit Squigs semantics or matching Ethereum contract `0x8c9a02c0585200c4c65608df6b8def543d33792a` attaches to a Passport. Bounty donations never masquerade as eligible entries. Source-confirmed Maw burn/digestion has its own major fact; swallowed is not burned. A verified source digestion suppresses normal current holdings while preserving artwork, discoveries and raw chain history. Source corrections can retract this derived status. It does not rewrite blockchain events or assert that an arbitrary sink address is mathematically irrecoverable.

## Import state and boundaries

`IntegrationSource` tracks configuration/validation, schema fingerprint, forward and reconciliation cursors, observed available/imported time bounds, attempts/success, backfill exhaustion and warnings. `SyncRun` retains bounded counts (scanned rows versus inserted/updated/skipped event slots, unresolved active slots, failed rows), cursor start/end, completion and safe error codes. `ImportRejection` retains source record ID, attempts and resolution, never the raw private row. A lock holder marks a previous RUNNING run interrupted before resuming its durable checkpoint.

States: NOT_CONFIGURED, UNVALIDATED, READY, PARTIAL, DEGRADED, ERROR. COMPLETE is reserved for independently established historical completeness and is never inferred from an empty page. The UI always says tracked history. Earliest/latest timestamps are observed import bounds, not proof no older source history exists. Production credentials and retention policies must be reviewed before lifetime claims.

Mutable timestamp sources use `(updated_at, primary key)` keysets; PostgreSQL timestamp text preserves microseconds in cursors. Other sources use durable ID/composite keysets with bounded rotating reconciliation after initial exhaustion. The worker additionally revisits one bounded primary-key page of timestamp sources per cycle to catch equal timestamps, old edits and failed records. Two forward pages and one reconciliation page is the default maximum per five-minute cycle, not a whole-database scan every cycle. Changes in a huge timestamp-less source may take a full rolling sweep to appear. `--replay` allows an operator audit; do not repeatedly pass it to resume an incomplete audit—continue from the saved cursor.

Each page selects at most 200 explicit columns/rows under external READ ONLY transactions and statement timeouts. Independent source failures do not stop later sources. A crash after events but before page checkpoint causes a harmless replay. A malformed row records a rejection and does not poison its neighbors; a rolling replay retries it. No truncation or external DDL occurs. Missing timestamps are rejected, never replaced with import time. `--since` is available for sources with the registered date column; unsupported sources fail rather than invent a range.

## Read models, privacy and metrics

Public and private timelines use indexed server-side category filters and `(eventAt, UUID)` keyset pagination, 24 entries per page, newest/oldest order. The existing blockchain Passport stays intact; its ecosystem section uses the same activity projection. MAJOR marks Maw disposition/digestion and Bounty wins, STANDARD meaningful game/collection records, DETAIL individual image usage. ALL hides DETAIL to prevent floods; category views retain it.

Public profiles must be public. Discord-derived activity additionally requires Discord visibility, wallet-derived activity requires wallet visibility, and provenance respects wallet visibility and dirty projections. Public Squig events do not publish an attributed Collector identity. DTOs expose only labels, time, token, approved image, allowlisted game/item/reward details and validated explorer transaction links. They omit source IDs, raw metadata, Discord IDs, hidden wallet associations, correction evidence, moderation notes and authentication information.

Duel counts include only completed rows, one participation per role. Wins/losses use the recorded winner, not payout results; unique/most-used Squig and largest wager are computed from those rows. Squig win rate is wins/completed recorded participations. Survival metrics sum one player observation per game; first/second/third use placement, not a fabricated game finish or win rate. Marketplace metrics count confirmed canonical purchases and distinct recorded item identities; refunds are separate. Creator counts deduplicate submission/live rows, retain private declined counts, sum approved reward points and count recorded milestones. Gallery usage is exact URL matching of source-recorded usages; it is not proof of copyright, wallet ownership, or unrecorded historical uses.

## Operations

```
npm run integrations:validate
npm run sync:uglybot -- --pages 2
npm run sync:gauntlet -- --pages 2
npm run sync:images -- --pages 2
npm run sync:activity -- --pages 25
npm run sync:uglybot -- --since 2026-06-01 --pages 2
npm run activity:reattribute -- --discord 123456789012345678
npm run activity:reattribute -- --wallet 0x0000000000000000000000000000000000000001
npm run activity:reattribute -- --collector <uuid>
npm run worker:ecosystem -- --once
```

`integrations:validate` performs only external SELECTs, schema/estimated-row inspection and permission introspection; writes validation status only to UglyDex. A role with write privileges is reported, never tested by attempting a write. Use `/admin/integrations` for coverage, `/admin/activity` for source/record/Collector/Discord/wallet/token/type lookup, runs and rejected records. All require existing admin authorization outside development. A missing optional field remains unavailable. Schema incompatibility: compare inventory, update the adapter with tests, then explicitly replay; never repair external tables from UglyDex. Review rejections and source availability before announcing coverage.

## Phase 4 consumer

Progression consumes this local evidence layer and confirmed provenance projections. Activity insert/update/delete triggers queue both prior and current Collector/Squig subjects. Source correction, slot retraction, token correction and reattribution therefore reverse dependent XP/achievements without external reimport. PUBLIC source content and confirmed Collector attribution are eligibility prerequisites; token-only facts can qualify for Squig progression independently. Payment amounts never scale XP. Progression audit/level milestones remain derived records and are never written back into CollectorActivity as fake source events. See [progression](progression.md).
