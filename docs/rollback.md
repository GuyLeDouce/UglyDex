# Rollback and incident recovery

Preserve evidence: commit, migration version, backup reference, UTC interval, safe error codes and affected token/feed IDs. Disable only affected workers first; a privacy regression may require taking affected public routes/web offline immediately. Never publish secrets or internal evidence in an incident note.

| Incident                           | Code action                                                            | Data action / gate                                                                                                                                                                          |
| ---------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bad web release                    | Roll back to a known compatible image; run readiness and smoke         | Phase 8 schema is additive. Check old code behavior before reopening traffic. No automatic down migration.                                                                                  |
| Bad worker release                 | Disable its control; wait for bounded task to drain; deploy known code | Resume cursor only after inspecting last successful batch. Confirm no duplicate ledger records.                                                                                             |
| Migration failure                  | Stop rollout and workers; keep last compatible web only if safe        | Backup current state. Reproduce on recovery DB, inspect Prisma history/drift. Explicit reviewed remediation only; never blind migrate reset/resolve.                                        |
| Bad progression/collections replay | Disable corresponding workers; restore correct evaluator               | Fix source/identity first; targeted subject rebuild where possible. Compare deterministic grants/evidence. Avoid replacing the entire database.                                             |
| Erroneous collectible import       | Retire incorrect public record; preserve audit                         | Re-import corrected reviewed manifest with revision checks. Never delete historical approvals; validate cached display fallback.                                                            |
| RPC/Reloaded indexing bug          | Disable blockchain, then dependent derived workers if evidence corrupt | Verify start/cursor/hash and raw facts. Use targeted provenance rebuild for projection defects; source resync only for proven raw gaps. Deep reorg requires operator review.                |
| Edition indexing inconsistency     | Contract automatically disables; inspect code and anomaly              | Ledger transaction rolls back. Correct adapter/RPC and re-enable explicitly. Bounded reorg rebuilds affected balances; deep reorg or replay limit remains failed. No ad hoc cursor jumping. |
| Legacy source outage/correction    | Disable ecosystem if repeated failures; retain indexed web state       | Validate schema/SELECT privileges, run bounded pilot/targeted reimport. Reattribute only affected identities and rebuild their derivatives.                                                 |
| Privacy regression                 | Disable affected public surface immediately                            | Fix projections/cache authorization; revoke sessions if credentials involved. Third-party cached/downloaded social images cannot be recalled; request purge where available.                |
| Database loss/corruption           | Deploy maintenance/closed public service                               | Restore reviewed backup into isolated recovery DB, run full drill/verification/privacy smoke. Human-approved datasource cutover is distinct from code rollback. Preserve old DB.            |

Replays should match the fault: raw-source resync for missing/corrected facts, targeted activity reimport for normalized source corrections, provenance rebuild for identity/period projection, progression rebuild for XP/achievement derivation, collections rebuild for discoveries/set snapshots. A global rebuild is justified only when the affected scope is global.

Independent kill switches: `production:worker -- --service <service> --mode DISABLED`; `editions:control -- --id <registry-id> --mode disabled`. Disabling does not need a production enablement override. Confirm no lock-held in-flight task remains before manual repair. Core workers back off exponentially and disable after three consecutive task failures; Edition contracts disable on the first inconsistent batch.

Phase 8 migrations add tables only. Apply migrations before new workers start; pause workers during migration and rollout validation. The preceding release can coexist with added tables, but lacks Phase 8 operational safeguards. Rolling code back does not erase Edition events or registry approvals. Never promise zero downtime during a database recovery.

## Phase 9

After code rollback or source remediation, old launch evidence is invalid for the new revision. Rerun safe verification and affected gates. Interrupted ReplayProof rows are never success; resume engines then run a new A/B pair. Do not restore production solely to erase an unstable derived replay.

Restore an older archive with the matching release's inventory verifier first. Phase 9 inventories include LaunchGate/ReplayProof; a Phase 8 archive does not contain those tables. Validate the old archive at its original schema on an isolated recovery database, then apply forward migrations and run the new checks. Never bypass inventory failures or mark an incompatible archive verified merely because pg_restore completed.
