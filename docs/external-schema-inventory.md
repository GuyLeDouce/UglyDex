| UglyBot `DATABASE_URL_POINTS`                                             | `UGLYBOT_POINTS_DATABASE_URL`    | Holder point mappings, not a CHARM balance ledger                           |
| Gauntlet `GAUNTLET_DATABASE_URL` / `DATABASE_URL` / `DATABASE_PUBLIC_URL` | `GAUNTLET_DATABASE_URL`          | Main games; code also has DRIP fallback                                     |
| Gauntlet `DATABASE_URL_SURVIVAL`                                          | `GAUNTLET_SURVIVAL_DATABASE_URL` | Separate history DB; legacy typo `DATABASUE_URL_SURVIVAL` accepted upstream |
| Gauntlet `DATABASE_URL_IMAGE`                                             | `GAUNTLET_IMAGE_DATABASE_URL`    | Live image library, approval notifications                                  |
| ImageSubmit `DATABASE_URL`                                                | `IMAGE_SUBMIT_DATABASE_URL`      | Normally same physical DB as Gauntlet images, separate pool                 |
| Gauntlet `DATABASE_URL_DRIP`                                              | Not imported                     | Routing overrides; not proof of Discord identity or wallet control          |

Variables may share a physical database, but UglyDex does not guess fallbacks. Set each explicitly with read-only credentials. Never point UglyDex `DATABASE_URL` at an external database.

## Source files and limitations

UglyBot: `index.js` schema functions and pool wiring; `modules/squigDuels.js`, `marketplaceCommand.js`, `bountyVaultCore.js`, `bountyVault.js`, `mawEvent.js`, `madlibSchema.sql`, `madlibStore.js`, `mawRarity.js`. Bounty voting persists aggregates from Discord reactions; no individual-vote table found. Portal events, mini roulette and miscellaneous DRIP payouts do not provide a complete durable activity ledger. No general authoritative CHARM balance/transaction table was found. Never reconstruct a balance from this partial history.

Gauntlet: `src/db.js`, `survivalStore.js`, `imageStore.js`, `squigTraitSnapshot.js`, game modes and reward webhook. Trait snapshots are fetched/cached in memory and logged to Discord; no persistent per-game Squig snapshot table was found. Group Gauntlet, riddles and fortune cannot be attributed a fabricated historical mode from these tables. Wallet resolver discovers aliases and does not enforce verification/guild filtering; UglyDex deliberately requires canonical verified evidence and explicit guild scope.

ImageSubmit: `migrations/001..005`, `src/db.js`, `app.js`, `config.js`, `eras.js`, `uglyCityMilestones.js`, `docs/CURRENT_CONTRACT.md`. Discord OAuth uses identify + guilds; UglyDex uses its own identify-only flow. There is no separate approved-creators table: derive contributions from approved rows. Reward points are eligibility/metadata, not confirmed payout. Configurable `LIVE_IMAGE_TABLE` and schema/search_path repairs exist; Phase 0 supports canonical public tables and reports incompatible deployments instead of guessing.

## Canonical Squig dataset

Both UglyBot and Gauntlet default to Ethereum contract `0x8c9a02c0585200c4c65608df6b8def543d33792a`. Source corroboration is not on-chain deployment verification; runtime RPC checks chain, bytecode and ERC-721 support.

- `metadata.csv`: 1–4444 `tokenID`, name, description, file_name, `attributes[Background/Skin/Type/Status/Body/Mouth/Eyes/Head/Special/Legend]`. `file_name` is not a resolvable image URL.
- `Squigs_Reloaded_Token_UglyPoints.csv`: canonical **Total UglyPoints**, Status, Legend, per-trait point breakdown and old Overall/Collection Rank. Do not sum trait points to recreate totals.
- `Squigs_Reloaded_Traits_Only_UglyPoints.csv`: `category,traits,uglypoints`, used for trait/game HP lookup; not token total ranking.
- `modules/mawRarity.js` is the canonical Maw calculation: 31 legends share rank 1; nonlegendary tokens sort by total points descending then numeric token ascending, beginning rank 32. Tiers: legendary <32, epic <444, rare <1111, uncommon <2277, common thereafter. Old CSV Overall/Collection Rank and the retained average-rank helper are **not the current Maw Rank algorithm**.
- Phase 0 exports a provenance-pinned data snapshot by running only this pure ranking module in the inspection snapshot; runtime imports the resulting values. No second scoring implementation. OG means explicit Status `OG`; no inference from token number. Metadata traits remain canonical. Store hashes and source revision with imports. Future updates should re-export from the reviewed upstream implementation.

Production schema, permissions, row counts and historical completeness remain unverified until read-only connection URLs are supplied. Previously committed production credentials in any ecosystem repository must be rotated by its owner; UglyDex does not copy or alter them.
